# 媒体创作的中文菜单与交互

图片、即梦 / MiniMax 视频、Omni、Muse 和配音统一采用中文创作菜单。技术能力清单、命令参数和素材处理中间结果留在内部执行流程，面向用户展示实际创作选择。

## 根据对话进度展示

1. **用户只说想生图、做视频或配音**：先了解想创作的内容。需要选择模型时，只展示当前任务相关的模型名称与用途，用“创作模型 / 适合什么需求”两列表格，给默认推荐加粗。用户可以回复名字、编号或直接描述偏好，AI 按刚才展示的菜单理解编号，不要求记模型标识。
2. **已经选定模型**：跳过模型介绍，只展示该模型实际支持的“想设置什么 / 可以怎么选”。默认选项加粗，每项用一行说明。图像关注内容、比例、清晰度和张数；视频关注内容、时长、比例和素材；配音关注文案、音色和表达方式。不要把所有模型的全部参数堆在一张表里。
3. **用户已经说清要求或授权自动安排**：直接按已知选择和适用默认值执行，不为了展示菜单再让用户填一次表。可以简短说明“按 8 秒、竖屏、使用你发来的参考图制作”。
4. **还缺少关键内容**：一次只补问当前真正需要的 1–2 个问题，例如“想拍什么内容？”“成片想做多少秒？”参考素材用途不清楚时问“这张图是用来参考人物，还是作为开头画面？”不要用内部字段名提问。
5. **用户调整设置**：接受“改成竖屏”“换第二个”“人物只做口型”“清晰一些”等自然语言，沿用其余已选配置。调整若影响模型或素材要求，简短解释实际差异，不静默换模型、换时长或裁剪素材。

模型选择是已有授权的一部分：用户已经选好或授权 AI 挑选时不重新确认；尚未授权代选时用简短推荐帮助选择。不要把“看看菜单”视作提交生成任务的授权。

## 菜单的内容与排版

- 使用紧凑的两列表格，列名用“想设置什么 / 可以怎么选”或“创作模型 / 适合什么需求”；每行一个选择，默认项加粗，可给每个设置配一个直观图标。
- 用“画面内容、多少秒、横屏/竖屏、清晰度、图片张数、人物是否出声、参考图片、开头画面、结尾画面、续写视频、朗读内容”等中文。
- 模型名称可以保留产品名，但不展示内部调用标识、参数名、协议要求、上传地址、编码格式、真假值、接口路径或机器返回对象。用户明确索要技术说明时再提供。
- 选项必须来自所选模型实际能力。**人物静音口型是 Muse 的已接入选项**，不能复制到所有视频菜单；Omni 当前成片约 10 秒，不承诺任意秒数；即梦 2.5 的时长只列 15 / 30 秒；MiniMax 普通版不列视频参考，Pro 版按其自身规则展示。
- 某种设置应通过创作描述表达时，在内部写入相应提示词，不编造独立控制参数。配音的情绪可用音色描述表达，不新增不存在的语速、音量、静音或时长字段。
- 菜单后只给一句自然的下一步，例如“告诉我想拍什么、做多少秒；有素材直接发给我。”用户已经说明的信息不再追问。

## 获取菜单与内部能力

以下都是 AI 在项目根目录执行的内部命令，不要求用户运行：

| 创作类型 | 中文菜单 | 所选模型菜单与内部能力 |
| :--- | :--- | :--- |
| 图片 | `python scripts/ai_image.py list-models` | 增加 `--model <所选模型>` 只显示该模型设置；`--json` 获取内部能力 |
| 即梦 / MiniMax 视频 | `python scripts/minimax_video.py list-models` | 增加 `--model <所选模型>`；`--json` 获取内部能力 |
| Omni 视频 | `python scripts/omni_video.py list-models` | 增加 `--model <所选模型>`；`--json` 获取内部能力 |
| Muse 视频 | `python scripts/muse_video.py list-models` | 单一模型菜单；`--json` 获取内部能力 |
| 配音与声音克隆 | `python scripts/ai_audio.py list-models` | 增加 `--model <所选模型>`；`--json` 获取内部能力 |

菜单只说明当前 CLI 接入范围，不当作服务端实时能力或成片保证。遇到具体限制时用白话解释其对本次创作的影响。

## 素材处理由 AI 执行

不让普通用户准备协议地址、转换编码或操作上传脚本。按对应模块的真实输入方式处理素材：

| 模块 | 内部素材处理 |
| :--- | :--- |
| 图片生成 | 本地参考图交给现有 `ai_image.py --input-images`，脚本自行上传，不预先重复上传。当前输入为本地路径；用户提供链接时，由 AI 准备可用素材或如实说明局部能力限制，不把链接冒充本地路径，也不伪造上传元数据。 |
| 即梦 2.0 / Mini 2 | 本地图片、视频和声音先调用已有上传脚本，从结果提取 `tmp_url` 填入对应数组；已有可用链接直接传入。Mini 2 的视频或声音需配至少一张图片。 |
| 即梦 2.5 | 本地素材可直接交给脚本自动上传，已有链接直接使用；不重复上传。 |
| MiniMax H3 | 本地素材可直接交给脚本按自身规则处理，不额外制造上传步骤；保留其首尾帧、多图、声音与短视频的校验。 |
| Omni / Muse | 本地素材由 AI 调用现有上传脚本后填写返回地址；已有可用链接直接使用。Muse 续写视频先在本地实测时长再上传，等长或长于目标的视频不得提交。 |
| 声音克隆 | 交给音频脚本检测并上传一个本地样本；当前不能直接把远程链接传作声音样本。不要为统一菜单跳过时长检测，或在外部先重复上传。 |

上传过程、字段映射和返回对象不复制进用户菜单。进度用“正在检查素材”“素材已准备好”“正在生成”等简短话术，只有确有状态依据时才报告；最终作品正常展示。素材失败、超限或能力缺失时，说明实际影响并完成其他可做部分，不伪造进度或产物。

具体能力见 [图片](ai_image.md)、[即梦 / MiniMax](minimax_video.md)、[Omni](omni_video.md)、[Muse](muse_video.md)、[配音](ai_audio.md) 和 [上传](upload.md)。
